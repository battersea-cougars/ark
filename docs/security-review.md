# Security review, 23 October 2026

The pre-launch review's security parts ([#148](https://github.com/battersea-cougars/ark/issues/148), section 3), on
`team/review` at `c735bf9`. It looked at the code only: no request went to dev or production. It covers every route in
the team app's Worker (`apps/team/worker`: 118 routes in the table, sign-in's own under `/api/auth/`, the Sentry tunnel)
and the website's live routes (`apps/web/src/pages` with `prerender = false`, and its middleware).

Earlier reviews (2026-10-06, 2026-10-09) are in [ADR 0036](adr/0036-api-security.md). This one found one High, fixed,
and no Medium in the code; what's left open is small or a decision.

**Severity:** High, someone can do what their role shouldn't let them; Medium, a weakness that needs something else to
go wrong first; Low, a small gap or hardening; Info, worth knowing.

## Checked and fine

- **Authorization by action** (ADR 0024): every route in the table declares an action, checked by `handleApi` before
  the handler, and the routes open to any signed-in member check the record: the scoresheet only by whoever holds it
  (an admin for a finished game), a draft pick only by the captain on the clock (or `run:Draft`), a team's look only by
  its captain, votes only by players and never for yourself, step-back by `manage:Tournament` (or `run:Draft` for the
  draft's own steps), sign-ups always for `c.memberId`.
- **IDOR**: every two-id path checks the second belongs to the first (a game, team, goal or penalty to its tournament;
  a passkey to its member). `/api/me/*`, announcement dismissal and notifications are always the caller's own.
  The grant rules (nobody gives what they don't hold; nobody changes someone who can do more) hold on every member
  change now, and the last-admin guard is inside the statements that write.
- **Per-caller filtering** (ADR 0036): emails, phones, payment references, ratings, roles, outs, no-shows, walk-ins
  and entered teams' contacts are filtered in the club read's SQL, and a change's reply the same way.
- **Audit log** (ADR 0095): every non-GET route declares one; the opt-outs are members' own changes, plus the Gmail
  reconnect's start and the test email, whose handlers record their own.
- **Rate and body limits** (#73, ADR 0055): per address, per member's changes, sign-in, passkeys and joining; bodies
  read up to 1 MB (16 KB for sign-in, 2 MB for an import, 4 MB for a tournament with logos) before parsing; JSON only.
- **CSRF**: every change must carry the app's own `Origin`, or `Sec-Fetch-Site: same-origin`, and JSON; GETs change
  nothing. The website's form relies on Astro's origin check (finding 19).
- **Cookies**: session, code nonce, passkey nonce and Gmail round trip are `__Host-` on https, `Secure`, `HttpOnly`,
  `SameSite=Lax`; tokens are random and stored only as SHA-256. Sessions rotate daily and end within a year.
- **Headers and CSP**: both apps send the same set from the Worker and `public/_headers`, held equal by tests; the
  team app allows one inline script by hash and only Turnstile from outside.
- **Turnstile**: checked on the server with the visitor's address and the form's action (now on both sites); the
  secret never reaches a page.
- **Passkeys**: RP ID and origin are the request's own, user verification required, challenges single-use and spent
  before the signature's checked, the counter guarded against copies.
- **Break glass**: never a web route; a script writes one code, claimed by the first browser to ask, on the record,
  and every admin hears.
- **Gmail reconnect**: state and PKCE verifier in a `__Host-` cookie checked on the callback, which needs a signed-in
  `manage:Settings`; the refresh token is sealed in D1 and never sent or logged.
- **Dev-only routes** (ADR 0123): the simulator exists only where `SITE_ENV` says `dev` or the local Vite server says
  `local` with no `SITE_ENV`; elsewhere a 404 for everyone. Dev sign-in and the auto admin need `TEAM_ENV` `local` and a
  private address. Dev mail is refused on production.
- **Uploads**: team logos must be PNG, JPEG or WebP data URLs under 200 KB (no SVG); there's no other upload route.
- **Website forms**: fields trimmed and capped, email headers stripped of line breaks, everything echoed escaped,
  redirects to fixed paths only, enquiries forgotten after 12 months.
- **Secrets in logs, errors and replies**: the log masks emails and hides secrets by key; Sentry collects no bodies,
  cookies, headers or query strings, and cleans every event the same way; no route returns a token or a code (the
  on-screen code is local only). The Sentry tunnel forwards only to our own project.
- **docs/secrets.md and Bitwarden**: every other name `npm run secrets` lists for dev is documented. Only dev's
  project is listed with this machine's token; production's names weren't compared.
- **Unused packages**: none found. Those no import names (`@capacitor/ios`, `@astrojs/check`, the Studio's React and
  styled-components) are platform or peer dependencies.
